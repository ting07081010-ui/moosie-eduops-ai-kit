# v0.3.0 — Claude Provider and Human Approval Gate

This release adds Claude as an optional provider and a human approval gate for parent-facing text. The Claude pilot is in progress: the existing prompts, schemas, and evals still run through the same caller, and live Claude output quality is still being reviewed against the rubric. This is not a finished Claude-only product. This note does not report live quality scores.

## Added

- Optional Claude provider through the official Anthropic SDK (`AI_PROVIDER`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`) (#22)
- Fake-data provider demo (`npm run demo`) with `--dry-run` / `--mock`, using `examples/fake-data/classroom-observation.json` (#22)
- Human approval gate: `createDraft`, `approveDraft`, and `outgoingText` (#23)
- Claude prompt caching on the shared system prompt (`cache_control: ephemeral`). Prompts shorter than the model's minimum cacheable length are not cached (#23)
- Optional `ANTHROPIC_RISK_MODEL` for the parent-message risk check only (#23)
- Live parent-message and privacy-risk evals against the selected provider, with `--report` to write a JSON report (#23)

## Improved

- The OpenAI chat-completions path stays in place when `AI_PROVIDER=openai`, or when no Anthropic key is set (#22)
- Live evals now call the shared provider switch instead of a hard-coded OpenAI request (#23)
- CLI and LINE startup messages name the missing key for the selected provider (#22)
- PII scanner ignores the `@anthropic-ai` package scope so it is not flagged as a LINE ID (#22)

## Behavior change

Drafts start as `pending`. Only a draft returned by `approveDraft()` can produce sendable text, and only when `approvedBy` is `teacher` or `admin`. A draft the risk check marked `block` cannot be approved. Forging `status: "approved"` does not produce outgoing text. Model output by itself is not sendable.

## Upgrade notes

Copy the new variables from `.env.example` into `.env`. Do not commit real keys.

| Variable | Purpose |
|---|---|
| `AI_PROVIDER` | `claude` or `openai`. Optional. |
| `ANTHROPIC_API_KEY` | Required when the selected provider is Claude. |
| `ANTHROPIC_MODEL` | Claude model id. Defaults to `claude-sonnet-5-5`. |
| `ANTHROPIC_RISK_MODEL` | Optional cheaper Claude model for the parent-message risk check only. Defaults to `ANTHROPIC_MODEL`. |
| `OPENAI_API_KEY` | Existing OpenAI key. |
| `MODEL` | Existing OpenAI model. Defaults to `gpt-4o-mini`. |

If `AI_PROVIDER` is unset and `ANTHROPIC_API_KEY` is set, the kit uses Claude. Otherwise it keeps the previous OpenAI behavior.

The approval gate changes how sendable text is produced. Call `createDraft()`, then `approveDraft()` with `approvedBy: "teacher"` or `"admin"`, then `outgoingText()`. `outgoingText()` throws for a pending draft, a blocked draft, or any object that was not returned by `approveDraft()`. A person approves the draft. The model does not.

`npm run demo -- --dry-run` still prints a fixed fake sample and does not call a model. A live `npm run demo` prints drafts for review; it does not mark them approved.

## Privacy

This release continues to use fake and de-identified data only. No real student data is included. The classroom observation uses student code `S-001`. Real student data should be de-identified before it is sent to Claude or any other model. Live Claude privacy-risk evals can be saved with `npm run eval -- --report <file>`. This release does not include measured scores from those runs.
