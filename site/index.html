這是什麼專案

Moosie EduOps AI Kit 是一套開源參考工具組，提供可重用的 prompts、JSON schemas、合成資料、CLI 與 LINE demo、evals 評估與隱私處理模式。它是早期、可在本機執行的參考專案，幫小型教育團隊看見「草稿先行、老師最後決定」的工作方式，不是通用家教 app、校務管理系統，也不是完整產品或正式服務。

同一專案裡有一個離線規則式示範「Moosi 說」：把老師打字的課後紀錄變成課後英語學習圖卡草稿。下面用一個固定合成案例，把它的資料來源、規則檢查與人工核准走一遍。

Moosi 說流程（固定合成案例）

本區全部內容都是固定的合成展示，沒有即時生成，也不會傳送任何訊息。各步驟狀態皆為「靜態流程示意」。

步驟一：合成老師紀錄 靜態流程示意 狀態 teacher_input · 合成示例

固定案例學生：S-007，暱稱 Sunny，程度 Beginner，單元 Unit 5，名冊弱詞 ["grapes"]。弱詞是虛構 fixture 欄位，用來讓離線示範選練習焦點，不是診斷，也不是模型推論。

Unit 5 水果課白名單：apple、banana、grapes；句型：I want some {fruit}, please.

老師打字紀錄（逐字取自 demo 來源 SAMPLE_TRANSCRIPT）：

S-007 在 Unit 5 水果課上能說出 apple 和 banana，grapes 的字首 g 還需要多練習。
請媽媽在家陪 S-007 玩買水果遊戲，練習說 I want some grapes, please。

步驟二：規則檢查 靜態流程示意 狀態 checking · 規則比對，不是 AI

  • 白名單檢查：逐字稿裡的每個英文單字都必須在允許範圍內（單元單字、句型用字或少數明確列出的附加字），超出範圍就整份退回。
  • 弱詞檢查：練習焦點必須來自所選學生的名冊弱詞（這裡是 grapes），而且同一分句要有明確的練習提示（例如「還需要多練習」），只提到單字不算數。
  • 證據檢查：成功產生的圖卡每一個欄位（key_words、sentence、weak_point_zh、home_mission_zh）都要有對應 evidence，其段落 ID 如 T-01、T-02；缺任何一項就退回補充。

步驟三：圖卡草稿 靜態流程示意 狀態 pending · 草稿

通過檢查後，demo 以固定樣板規則產生 4:5 圖卡草稿（viewBox 1080x1350），固定樣板規則產生，不是 AI 生成。demo 會為圖卡內容計算 SHA-256 內容雜湊（此處不列出雜湊值），並附上來源寫法：樣板規則產生的示範草稿，不是 AI 生成，也沒有使用語音辨識。

固定版式合成預覽：為完整呈現所有欄位，版式經調整，非 demo 匯出原檔；欄位文字與來源一致，此處不列出雜湊值。

步驟四：人工核准 靜態流程示意 狀態 approved · sent: false，不會傳送

只有老師或管理員能核准，AI 不能核准。核准時後端用當下卡片內容重新計算雜湊並比對：缺少雜湊、雜湊不符、尚缺逐字稿證據、重複核准都會被拒絕。來源寫法例如：「這份草稿尚缺逐字稿證據，不能核准；請補充老師觀察後重新產生。」、「核准需要附上圖卡內容雜湊，缺少雜湊不能核准。」、「內容雜湊不符，圖卡可能已被修改，不能核准；請重新預覽後再核准。」

核准只改變本機草稿狀態（sent: false），不會傳送訊息給家長，也不會寫入其他系統。

在本機操作文字流程 demo

上面四步是固定合成展示；要親手操作真正的 demo，請看 Moosi 說 demo 操作說明↗。文字流程需要 Node.js 20.12.0+（Node 20）、21.7.0+（Node 21）或 Node 22+；在本機執行 npm run demo:moosi-say 後開啟 http://127.0.0.1:3107（預設只綁定 127.0.0.1 loopback）。ffmpeg 與 ffprobe 只在音訊功能需要，打字的文字流程不需要它們。

兩個固定反例

以下兩個反例的文字皆逐字取自 demo 程式碼與輸出，沒有改寫。狀態皆為「靜態流程示意」。

反例一：證據不足 靜態流程示意 狀態 needs_teacher_input · 需老師補充證據

這份逐字稿提到了全部單元單字，但對 grapes 沒有明確的練習提示（只說「能說出」，沒有「還需要練習」這類觀察）：

S-007 在 Unit 5 水果課上能說出 apple、banana 和 grapes。
請媽媽在家陪 S-007 玩買水果遊戲，練習說 I want some grapes, please。

結果狀態為 needs_teacher_input，demo 回傳老師可讀訊息：「逐字稿沒有明確記錄名冊弱詞（grapes）需要練習；已交回老師補充觀察後再產生圖卡。」不產生圖卡、沒有內容雜湊、沒有可核准物件，請老師補充觀察後重新產生。

反例二：超綱單字 orange 靜態流程示意 狀態 rejected · 退回

逐字稿在固定範例後多了一句「今天也練習了 orange。」orange 不在 Unit 5 白名單內：

demo 回傳錯誤訊息：「紀錄中有本單元以外的英文單字（orange），已退回，不會產生圖卡。」狀態為 rejected／退回，不產生圖卡。

另一條路：其他 LLM 工作流的審核閘門

專案裡其他 LLM 工作流用的是 src/core/approval-gate.mjs 的 createDraft → approveDraft → outgoingText：草稿先是待核准，一定要人類老師或管理員核准才算通過；風險檢查判為 block 的草稿不能核准。這和 Moosi 說規則式雜湊綁定本機核准不是同一條路。已核准的 LLM 草稿是「可以產生對外文字」的狀態，不代表那些訊息永遠不會送出；實際是否送出要看各工作流與 provider 設定。程式來源：approval-gate.mjs↗。

工具組其他工作流

以下卡片各用一句話說明既有內容，狀態沿用專案自述；都不代表已經產品化。

  • 行政任務擷取 Stable

  • Prompt 評估 Stable

LINE demo：兩條不能互換的路

Experimental 兩者都只供本機測試，需要在專案根目錄 .env 設定 OPENAI_API_KEY、LINE_CHANNEL_ACCESS_TOKEN、LINE_CHANNEL_SECRET。本網站本身不連接 LINE。

Quick reply 整合

指令：npm run line:quick-reply（舊名 npm run line 是同一個伺服器的別名）。傳一般文字的課後紀錄，再用 5 個 quick reply 操作：generate_summary、check_risk、extract_tasks、generate_practice、list_yellow_students。它不處理斜線指令。

Slash-command demo

指令：npm run line:slash-demo（舊名 npm run line:demo 是同一個伺服器的別名）。接受三個文字指令：/summary {json}、/risk <text>、/task {json}。說明見 slash-command demo 說明↗。

隱私、安全與人工作業邊界

  • 範例使用合成資料
  • 輸出是草稿
  • 家長訊息需人工審核
  • 網站程式不收集、不儲存、不傳送任何輸入

其他 LLM 工作流會把內容送到你設定的 provider（Claude 或 OpenAI）。送出前先去識別化，例如用 S-001 這類代號，不要送姓名、電話、地址、學校或家長聯絡方式，並先看過 provider 的資料處理條款。不要把「Moosi 說離線 demo 不呼叫外部模型」外推成專案裡所有流程都不外傳資料。

以上只是專案已實作做法的說明，不是法律或合規承諾；部署的人要自己負責取得適當同意、設定保留政策，並在需要時尋求在地法律意見。

註：託管平台可能依其政策保留一般存取紀錄；點出去的外部連結適用目標網站的政策。相關文件：PRIVACY.md↗、未成年人資料處理說明↗。

音訊功能說明（純文字，無上傳）

本網站沒有上傳按鈕，也沒有音訊播放控制。既有 demo 的音訊路徑只收自行生成的合成 Ogg／Opus 音調，在本機用 ffmpeg 正規化為 16 kHz 單聲道 PCM16 WAV；之後回傳的逐字稿是固定 mock 範例，和音訊內容無關，不是語音辨識。輸入上限 2 MiB、最長 60 秒。合成與成人老師聲明只是該 demo 的使用限制，不是身份或來源驗證。不得選取或上傳真人錄音，尤其不得使用兒童音訊。ffmpeg 與 ffprobe 只是音訊功能的額外需求，打字的文字 demo 不需要它們。
